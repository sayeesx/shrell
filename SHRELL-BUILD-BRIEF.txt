# SHRELL — BUILD COMPLETE ECOMMERCE BACKEND FROM SCRATCH

Act as a senior full-stack engineer and PostgreSQL architect.

## Project context
- Backend workspace is starting from scratch.
- Existing storefront frontend is approximately 40% complete.
- Sanity is already integrated into the Admin panel.
- Replace the old Cloudinary account with the new Shrell Cloudinary account.
- Website is already hosted on Vercel.

## 1. Audit first
Inspect the entire workspace, existing frontend, Admin panel, Sanity integration and old Cloudinary configuration.

Do not delete existing working code or create duplicate integrations.

## 2. Supabase — Complete ecommerce database

Connect the actual application to Supabase using `@supabase/supabase-js`.

Build a normalized, production-ready PostgreSQL database covering:

- Customers, profiles, authentication and addresses.
- Products, variants, SKUs, categories and brands.
- Vehicle compatibility (make, model, generation, year and variant).
- Inventory, stock movements and reservations.
- Shopping carts and wishlists.
- Orders, order items and order history.
- Payments, refunds and COD.
- Shipping, tracking and PIN-code management.
- Coupons, discounts and promotions.
- Reviews and customer questions.
- Admin roles, permissions and audit logs.

Requirements:
- UUIDs, foreign keys, indexes and constraints.
- Accurate INR pricing using appropriate numeric types.
- Atomic inventory and order operations.
- Prevent overselling and duplicate transactions.
- Version-controlled SQL migrations.
- Generated database types.
- Proper error handling.

## 3. Security

Implement strict Row Level Security (RLS).

- Customers can access only their own data.
- Admin permissions must be verified server-side.
- Public users can access only published catalogue data.
- Never expose service-role keys or private credentials.
- Validate all inputs server-side.
- Secure payment webhooks and prevent duplicate processing.
- Test customer isolation and privilege escalation.

- SEO content.

Use Supabase for prices, SKUs, inventory, orders and customers.

Maintain stable identifiers between Sanity and Supabase.
